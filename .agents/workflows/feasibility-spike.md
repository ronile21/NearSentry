# Workflow: Feasibility Spike

Use for unknown platform/vendor behavior such as Garmin presence detection.

1. State the hypothesis precisely.
2. Define success/failure criteria before implementation.
3. Prefer the smallest executable experiment.
4. Record device/OS/watch/app versions.
5. Capture observed results, including failures.
6. Classify the hypothesis as VERIFIED, DOCUMENTED, HYPOTHESIS, or REJECTED.
7. Update design/specification assumptions.
8. Create an ADR if the result changes architecture.
9. Do not turn spike code into production code without cleanup/review.
